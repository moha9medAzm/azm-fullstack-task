# ADR V2-0004- — Code-first errors + `react-i18next`; logical CSS for RTL

**Status:** Accepted · 2026-09-08 · branch `v2-full-scope`

## Context
Area 12 requires Arabic + English with RTL. The API already returns a stable error
`code`; the UI has hand-written CSS.

## Decision
- **Server:** error `message` is resolved from `messages/{en,ar}.ts` by `code` +
  `Accept-Language` (default `en`), falling back `ar → en → code`. The `code` in the
  envelope never changes, so the client can translate too.
- **Client:** `react-i18next` + `locales/{en,ar}.json`; a header switcher; choice in
  `localStorage`; `<html dir>` toggled on change. CSS uses **logical properties**
  (`margin-inline-start`, `text-align: start`, `inset-inline`) so RTL mirrors for
  free; a few explicit `[dir=rtl]` overrides only where needed.

## Consequences
+ One translation surface; RTL is mostly automatic; errors are translatable on both
  sides without changing the contract.
- Every visible string must move into a catalog — a real but one-time cost, gated to
  the 4 core screens for Story 01 and extended per story after.
